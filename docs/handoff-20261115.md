## 3. How the dry run is done (what worked today)

- `net.http_post` to `/functions/v1/whatsapp-reply-agent-dryrun` with `{dry_run:true, inline:true, message_id, brain_sha}` and the
  `x-crm-agent` secret from the vault; nothing is written or sent. Answers in `net._http_response` (kept a few hours).
- **Batches of about 40**, wait, then read in a **separate** statement (a statement only sees rows that existed when it
  started, so `pg_sleep` and the read cannot be one query). 124 at once hit the OpenAI rate limit.
- The cutoff must be **in the past**, and rows are matched by message id or by a dense number checked with `min(req-dn) = max(req-dn)`.
  The list used all day: last inbound message per chat up to `2026-11-15 11:00+00`, both numbers, not muted, not ignored,
  newest first; rows 1 to 512 are done (about 500 different chats).
- Artefacts to recognise: an old message run again leaves the ad out (sent once per chat) and reads its dates as «today»;
  a chat whose client also writes on the other number gets no reply by design; a deleted message never runs live.
- **No Node on this machine.** To run a piece of the agent locally: open the raw file of the commit in the Claude browser pane
  (`raw.githubusercontent.com/...`) and use the JavaScript tool on `document.body.innerText` (fetch is blocked there).
- **GitHub API** without a token is 60 calls an hour: a polling loop used it up. Poll CI at most every 20 seconds and stop
  after a fixed number of tries. GitHub CLI 2.104.0 is installed (Ahmed ran winget); it is **not signed in**. If he runs
  `gh auth login`, use `gh run watch` / `gh run view --log-failed` instead.
