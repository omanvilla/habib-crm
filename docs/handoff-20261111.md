## 4. How to change things safely (the routine used all along)

**Front end.** `index.html` boots `app-base-v15.html` and appends module scripts with `?v=` versions inside a JS string.
Bump the `?v=` of every changed file. Inside that string a closing tag must be written `<\/script>`, never `</script>`
(that broke the boot once). Many tests pin versions: update them with the version.

**SQL.** Write `db/changes/NN-name.forward.sql` + `.rollback.sql` (refuse if a replaced live body changed: md5 check),
copy the forward file byte-identical to `supabase/migrations/<version>_<name>.sql`, commit and push, then apply with
`apply_migration` by fetching the committed file:
```sql
DO $mig$ DECLARE r record; BEGIN
  SELECT * INTO r FROM extensions.http_get('https://raw.githubusercontent.com/omanvilla/habib-crm/<sha>/db/changes/NN-....sql');
  IF r.status <> 200 OR position('SQLNN (' IN r.content) = 0 THEN RAISE EXCEPTION 'fetch failed %', r.status; END IF;
  EXECUTE r.content;
END $mig$;
```
Test as a staff account inside a rolled-back transaction:
`begin; set local role authenticated; select set_config('request.jwt.claims','{"sub":"<profile id>","role":"authenticated"}',true); ... rollback;`
Last applied: **SQL89** (next free number: **90**).

**Edge functions.** Deployed as stubs that import the code from GitHub at a pinned commit:
`import "https://raw.githubusercontent.com/omanvilla/habib-crm/<sha>/supabase/functions/<fn>/index.ts";`
Before re-pinning, check that `main` holds no unpublished change you don't intend to ship (compare with the live pin).

**Agent prompts.** `brain.ts` / `knowledge.ts` reach the live agent only through `agent-prompt-sync` (copies them from
`main` HEAD into `whatsapp_agent_prompts`):
```sql
select net.http_post(url:='https://dmsckqjkcnsfmnzfjczz.supabase.co/functions/v1/agent-prompt-sync',
  headers:=jsonb_build_object('Content-Type','application/json','x-crm-agent',(select decrypted_secret from vault.decrypted_secrets where name='crm_reply_agent')),
  body:='{}'::jsonb, timeout_milliseconds:=60000);
```
Then check `select key,left(source_sha,7) from whatsapp_agent_prompts`. Open `crm_owner_notes` (status open, apply_now)
are appended to the brain as lessons by a trigger.

**Dry run of the agent.** `whatsapp-reply-agent-dryrun` (forced dry from its URL). Re-pin it to the commit under test,
then per message: `net.http_post(... '/functions/v1/whatsapp-reply-agent-dryrun', body {dry_run:true, inline:true,
message_id, brain_sha:'<full sha>'})` and read `net._http_response` (`send_preview`, `action`, `handoff_reason`,
`mustahiq_waitlist`, `meeting`). pg_net answers come back after ~30–90 s; poll, don't `pg_sleep`. Inline calls to the
live function (no `brain_sha`) also write nothing.

**Browser checks.** Claude in Chrome on Ahmed's PC (his sessions). Add `?v=...` to the URL to skip a cached index.
Heavy page testing once caused statement timeouts; go easy.
